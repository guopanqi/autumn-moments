# V0.2 行动与表现协议

## 为什么要拆开

生活游戏的关键不是点完出现一行“心情+8”，而是角色在空间中**完整做完一件事**。交互对象负责定义可以做什么；角色动作负责它看起来如何发生；世界状态只接受动作到达关键时刻后的效果。

## 一次标准行动

1. `World.pick` 在鼠标/触摸 raycast 命中 `Interaction.root` 后请求寻路。
2. `Character.follow` 到达 `Interaction.approach`；没路不会隔空执行互动。
3. `World.performInteraction` 调用无副作用的 `Interaction.use()` 计算效果，转向对象并执行 `onActionStart`。
4. `Character.act` 开始限时程序表演，在设定的归一化 `moment` 处仅调用一次 `onMoment`，由 `World.apply` 修改心情/金币并保存。
5. 表演结束调用 `onActionEnd`；任意移动、新目标或传送调用 `onCancel`，**同样**触发 `onActionEnd`。

重要：奖励不在用户点击、导航开始或表演开始时发放。中途取消（在 cue 之前）不发奖；cue 之后取消不回滚已发生的结果，也不重复发奖。

## 当前动作与暂定时序

| 动作 | 时长 | 效果 cue | 当前表现 |
|---|---:|---:|---|
| wave | 1.30s | 48% | 手臂轻挥 |
| sip | 2.65s | 57% | 桌上杯子隐藏，角色手持杯抬到面前，落下后恢复 |
| sit | 2.55s | 48% | 双腿弯曲，下沉后起身 |
| pet | 2.20s | 48% | 身体前倾伸手，小狗回应、跳跃、爱心上升 |
| rest | 3.25s | 53% | 下蹲靠近床、轻闭眼，完成后起身 |

程序化动画只是 V0.2 视觉演示，不表示已经有真实坐到椅面或卧躺于床的空间约束。需要骨骼/对象对齐与家具锚点后再迭代。

## 取消和对象生命周期

- 新的手动输入、点击另一目标、地点切换取消角色当前行动。清理回调必须始终执行一次。
- 不得将 UI 文字反馈当做动作事件；事件必须在动作进度中发出。
- 玩家持续移动时不能反复触发 `onCancel` 中的资源副作用。
- 物体 `onActionStart`、`onActionEnd` 只调整表现，不应直接改变存档。
- 地点间不共享临时对象或动作的引用；切换地点由公共 Player 持有动作并取消。

## 浏览器回归检查（必须手动观察）

- 点击茶杯，未走到前没有奖励；走近后杯子移动到手上；动作结束桌面杯子恢复。
- 刚拿起杯子时按 WASD，人物立即走路、杯子恢复，不发放未触发的心情。
- 喝茶过半再取消，奖励只发放一次；不会在页面刷新或换场景后再次发放。
- 小狗无人触碰也会看向附近玩家、呼吸和轻摆尾；抚摸出现短暂跳跃/爱心。
- 反复从公园和小屋切换，角色、镜头与物体不残留动作。
- 跑道和目标不可达时不隔空执行；移动端按钮取消动作语义一致。
