# V0.3 房间装饰实验

## 核心想法

家是一个可被玩家改变、并在下一次进入时依然保持变化的场所。首先实现最小的可修改性：**一种家具 → 空间落点 → 约束验证 → 真实物体 → 保存 → 刷新恢复**，而不是一次性实现大型建筑编辑器。

## 代码与身份

`src/decor/furniture.ts` 中 `HomeDecoration` 是小屋级的功能对象；编辑工具只在小屋可见。预设 ID 稳定：`plant`、`stool`、`lamp`，存档仅保存 prefab 名称、稳定的实例 ID、x/z 坐标及旋转角。渲染几何不是存档的权威数据；以后可替换为外部 glTF 而不丢布局。

```ts
type FurnitureKind='plant'|'stool'|'lamp';
type PlacedFurniture={id:string;kind:FurnitureKind;x:number;z:number;rotation:number};
```

## 规则

- 在小屋点击右侧的「布置小屋」按钮展开菜单，再选择物件，鼠标经过地板显示半透明预览；绿色=地面内且不重叠，红色=当前不允许。
- `R`/按钮旋转 90°；左键点击可确认；`Esc`/按钮退出；“撤销上一件”移除最后成功创建的实例。
- 摆放必须在小屋合法边界内，且不与静态/已摆放的障碍或当前玩家重叠。
- 确认摆放时，对茶、床、出口三个核心交互路径执行 A* 通达检查；若放置导致不可达则拒绝。
- 确认后将圆形碰撞代理加入 `Location.obstacles`，立即影响人走路与点击路径；撤销也同步移除。
- 保存到 `autumn-moments:v2`。读取时兼容 `autumn-moments:v1` 的心情、金币、地点。保存内容有基础结构验证，阻止不合法类型和坐标进入场景。

## 当前明确限制

- 圆形障碍是保守近似；家具旋转暂时只有视觉变化，不改变占地盒，后续需引入面向的包围盒与真实 NavMesh。
- 尚不能直接拖动已放置家具。撤销只按最后放置顺序，不是完整操作历史。
- 不保存 UI 正在放置的预览/撤销历史、人物位置和时间。
- 小屋家具只做演示，不消耗金币；购买/工作报酬循环应在之后的玩法阶段设计，不应借用装饰菜单偷加经济消费。
- 这是程序化模型占位，不应作为美术风格验收的唯一证据。

## 浏览器回归检查

1. 旧版本已有心情和金币的数据用户更新后状态仍然存在。
2. 进入家中选择绿植，预览随鼠标移动；红色区域点击不会创建物品；绿色空地点击成功。
3. 旋转并放置软凳；重新加载页面后绿植和软凳位置与朝向一致。
4. 放置后人物点击茶、床和出口仍能到达；尝试阻挡路径会出现提示。
5. 撤销上一件后，原位置重新允许人物通过，也可以重新放置。
6. 放置中切换到公园，再回家，预览自动取消，已提交的家具保留。
7. 在手机触屏浏览器选择/放置/撤销，并确认界面无关键操作遮挡。

## UI 修订

为了避免让工具面板持续遮住生活场景，V0.3 的布置面板默认折叠，仅在玩家主动点击「布置小屋」后展开；可随时关闭，关闭时取消未确认的预览。
